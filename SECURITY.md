# Security Policy

## Overview

FORBIDDEN-LORE-WIKI is primarily a static website generated by Python.

The project does not require a database, authentication system, server-side user accounts, or persistent browser storage.

Security issues are still taken seriously, particularly issues involving generated HTML, JavaScript execution, unsafe content handling, dependency vulnerabilities, or deployment configuration.

## Supported Versions

The current version on the `main` branch is the primary supported version.

Older generated versions may not receive security fixes.

## Reporting a Security Issue

Do not publicly disclose a serious security vulnerability before it has been reviewed.

If you discover a security issue, report it privately to the repository owner through the security/contact mechanism configured for the repository.

Include:

- A clear description of the vulnerability
- The affected file or component
- Steps required to reproduce the issue
- Expected behavior
- Actual behavior
- Potential security impact
- Any proof-of-concept information that is necessary to reproduce the issue

Please avoid including passwords, authentication tokens, API keys, personal information, or other sensitive information in a report.

## Examples of Security Issues

Security reports may include:

- Cross-site scripting vulnerabilities
- Unsafe HTML injection
- Unsafe JavaScript generation
- Arbitrary script execution
- Malicious content inserted into generated pages
- Dependency vulnerabilities
- Build-process vulnerabilities
- Unsafe deployment configuration
- Accidental exposure of secrets
- Unexpected network requests
- Unexpected collection of personal information

## Static-Site Security Model

The generated website is designed to operate without a backend.

The project intentionally does not require:

- Database credentials
- Authentication secrets
- API keys
- Password storage
- User account data
- Server-side sessions

The absence of these components reduces the application's attack surface but does not eliminate all security risks.

Browser-side JavaScript can still contain vulnerabilities, particularly when dynamically generated content is inserted into the DOM.

## Content Generation

Generated content should be treated as untrusted data when appropriate.

Dynamic content should not be inserted into HTML using unsafe interpolation when the content can contain arbitrary user-controlled or externally supplied markup.

Where applicable:

- Escape HTML text
- Avoid unsafe `innerHTML`
- Prefer DOM APIs for dynamic elements
- Validate generated values
- Avoid constructing executable JavaScript from arbitrary data
- Do not embed secrets in generated client-side files

## Secrets

Never commit secrets to this repository.
